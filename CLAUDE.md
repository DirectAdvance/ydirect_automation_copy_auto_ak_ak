## ⚡ ПРАВИЛО №1 — МАКСИМАЛЬНАЯ ПАРАЛЛЕЛЬНОСТЬ (ВСЕГДА ПО УМОЛЧАНИЮ, подтверждено Семёном 2026-07-14)

**В этом проекте всё, что можно делать параллельно — делать параллельно.** Не по одному.

- Независимые задачи (разные файлы / разные слепки / нет общего результата) → запускать **одновременно** несколькими агентами/тулами в одном сообщении.
- Зависимые (B нужен результат A) или **правки одного и того же файла** → строго последовательно (иначе конфликт записи).
- Типовая раскладка без коллизий: структура (`direct/slepki/<key>.json` — по файлу на слепок) ‖ движок (`create_set_*.py`) ‖ шаблон создания РК (`templates/direct/index.html`) ‖ UI слепков (`templates/direct/slepki.html` + `static/direct/slepki_ui.js`/`slepki_ui.css` — вынесены из index.html 2026-07-17) ‖ доки (`*.md`) — это РАЗНЫЕ файлы, можно параллелить. Бонус разбиения: правки РАЗНЫХ слепков теперь тоже не конфликтуют (разные part-файлы).
- Живой харвест по многим слепкам/аккаунтам → фан-аут по слепкам (каждый агент — свой слепок, свой файл вывода), потом слить.
- **После параллельного прогона — ОБЯЗАТЕЛЬНО верифицировать каждый результат самому** (diff/compile/факт), не считать «раз параллельно — всё ок».

### 🚀 Per-item фан-аут (правило Семёна 2026-07-14, «нужна максимальная скорость»)
**Любая задача вида «сделать/проверить X по N слепкам (или N типам сайта / N аккаунтам)» — запускать N ОТДЕЛЬНЫХ агентов параллельно (по одному на элемент), а НЕ один агент последовательно по всем.**
- Пример: gap-аудит по 12 слепкам → 12 агентов (по слепку), каждый пишет свой `_gap_<slug>.md`, потом слить. Не один агент на 12.
- Каждый агент — свой элемент, свой файл вывода (нет коллизии записи). Централизованная сборка/слияние результатов — после.
- Применять к: аудитам, сбору/харвесту, верификации, топапам — везде где элементы независимы.
- Исключение: правки ОДНОГО общего файла (structure.json, index.html, один .py) — только последовательно.

## 🔑 Ключевые факты (кодер tp6/tp7)

- **tp6 (Мастер кампаний, МК)** — кодер `{сегмент}_aon_n000_r0000_ct001_ag011_g00`.
- **tp7 (Товарные, ТК)** — кодер `{сегмент}_aon_n000_r0000_ct010_ag001_g00`.
- **В tp6/tp7 всегда `aon`** (независимо от таргетинга; aoff НЕ используем). `fmt`: ct001=МК, ct010=товарка (`create_set_plan.py:74-84`).
- **Имя кампании tp6/7** несёт метку таргетинга в конце: `автотаргетинг / КС / аудитории / КС+аудитории` (без типа оплаты CPC/CPA/CRM). UI-бейдж парсит метку из имени.
- **Квиз и «Неопределено» — НЕ учитываем при сборе слепка.**

## 🗂 Структура слепков (2026-07-17: разбита по файлам)

- **Источник правды — per-slepok файлы** `direct/slepki/<key>.json` (по одному на директолога) +
  порядок `direct/slepki/_order.json`. Монолита `slepki_structure.json` **больше НЕТ** на диске.
  Правка одного слепка = маленький diff одного файла.
- **Загрузка**: `slepki_store.assemble()` собирает единый `{"directologists":[…]}` в памяти (кэш по
  сигнатуре mtime+size частей). Совместимость: `_json("slepki_structure.json")` перехвачен в
  `automation_runtime._json` → `assemble()`, поэтому все читатели не менялись. **Прямых чтений файла
  быть не должно** — только `_json(...)` или `slepki_store.assemble()` (иначе пусто после разбиения).
- **Запись**: редактор → `slepki_store.write_directologists()` — атомарно (temp+os.replace) только
  изменившиеся части + `_order.json`. Никаких `os.replace` монолита.
- **Семейства правил создания** (`blueprint_targeting.ruleset_for` → `auto` | `custom`, было булево
  `auto`): `custom` (dmp и будущие B2B) = структура по splits, B2B-контент без числ. гейта, свои
  картинки, без фильтра «марка+модель». Семейство из записи: `auto:false` и/или `ruleset:"custom"`.
- **UI-группы дропдауна** «Слепок» (поле `ui_group`, НЕзависимо от ruleset): `auto` (салоны) /
  `auto_other` (gen_ses,avto_sk,avtolajt_bu,sk_krs — правила auto) / `other` (dmp — правила custom).
- **Онбординг прочего слепка по скринам** — skill `/direct-custom-slepok`.
