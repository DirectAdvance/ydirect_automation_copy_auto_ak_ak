## 0. Как устроен слепок (важно для понимания «удаления кампании»)

- Узлы tp хранят **плоский список `groups`**, а НЕ кампании. Каждая группа = `{name, items:[…]}`,
  у item есть `gc`, `gk`, `c` и **список `camp_names`** — все логические кампании кабинета, в которых
  эта группа участвует (загрузчик свернул регионы и объединил авто/КС-варианты одной ad-группы в
  ОДИН объект группы с `camp_names=[…]`).
- UI (`static/direct/slepki_ui.js`, `_campaignize`) строит «кампании» **виртуально**, группируя
  группы по строкам `camp_names`. Одна и та же физическая группа показывается под КАЖДОЙ своей
  кампанией. Поэтому «34 группы в кампании X» ≠ «34 отдельных объекта группы».
- **Нет** редакторной операции «удалить кампанию». Есть только `apply_remove_ct_group(slepok,site,tp,gc)`
  (`slepki_editor.py:843`) — удаляет item(ы) **по gc** во всём tp и чистит опустевшие группы.
  Он camp_names НЕ трогает и работает по gc, а не по объекту группы → см. риски ниже.

**Следствие:** корректное «удаление кампании» = убрать её строку из `camp_names` всех items, где она
есть, и удалить только те группы, у которых `camp_names` стал пустым. В моих данных таких пустых **нет**
ни в одном из 6 пунктов, где речь про камп-удаление → **ни одна группа физически не удаляется** в п.1 и п.2.

Camp-счётчик tp = число уникальных `camp_names` (для tp1/2/5) или число групп (для tp6/7, где группа=кампания).
