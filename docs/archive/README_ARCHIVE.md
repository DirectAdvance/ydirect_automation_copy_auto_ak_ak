## Комбинаторное РСЯ (tp1/tp2/tp5) + Имитация-прогон Павлова — 2026-06-24

### Комбинаторное РСЯ (tp1/tp2/tp5): заголовки/«б/у»/цены — 2026-06-24
Официальная миграция Яндекса: `TextAd` в ЕПК с **30 июня 2026** больше не создаётся как отдельный
тип, новые объявления идут как **`RESPONSIVE_AD`**; существующие в июле начнут автообновляться.
Источник: `https://yandex.ru/dev/direct/doc/ru/update-tga`.

QA созданных объявлений выявил 3 пробела в комбинаторном (ResponsiveAd), исправлено в v5 И куки-путях:
- **Заголовков было 3 → стало ~7 ПО КОДЕРУ.** Раньше `[модель, title2, бренд]`. Новый `_rsya_titles`
  (общий для `_build_tp1_from_pack`/`_tp1_pack_groups`/`_build_text_from_pack`): бренд-шаблоны
  («Новый {brand} у дилера», «{brand} в наличии в {город}», «Купить {brand} выгодно») + пул слепка
  (`_slepok_campaign_content`, 1 запрос на кампанию) + дженерик-добивка → `_fill_variants(…, 7)`.
  Капы подняты: `_RA_TITLES_CAP 5→7` (v501) и `grid_create.build_ad _dedup_keep(…,7)` (куки). Проверено
  live: 7/7 заголовков и на куки, и на v501. Сегмент «Общее» (тема, не марка) → `is_brand=False`:
  бренд-шаблоны НЕ применяем (иначе «Новый Автокредит/кредит у дилера»), добиваем пулом слепка.
- **«б/у» на не-Б/У сайте.** `_drop_used_car` применялся только в tp6/tp7; теперь и в tp1/tp2/tp5
  (заголовки через `_rsya_titles`, тексты явным фильтром). Мультибренд → 0 «б/у».
- **Цена не на всех + битое число (11212).** Дефолтный прайс-фид имеет промо-имена офферов
  «-35% renault arkana — за заявку» → `split()[0]='-35%'` (бренд-матч ломался, цена-мусор). Фикс:
  (а) `_price_feeds_for`/`_account_offer_prices` — берём ЦЕНЫ из предпочтительных фидов
  `_PRICE_FEED_PREFS` (zabronirovat-01-a · yandex-used-auto · yandex-catalog-model-design-custom-name,
  чистые имена), мердж; (б) чистка имени оффера в `_grid_feed_offer_prices` (срезаем «-N%»-префикс и
  «— за заявку»/«от … р» хвост). Куки-путь раньше цены НЕ ставил вовсе — теперь прокинут `price_map`.
  Баг `BANNER_PRICE_GREATER_THAN_OLD` (при `old==current` ставился `priceOld` → весь батч ads падал):
  `priceOld` ставим ТОЛЬКО при реальной скидке `old>current` (и в куки `create_full`, и в v5
  `_grid_set_ad_prices`). Live: цены проставлены на марках, что ЕСТЬ в фиде (BAIC/Lada нет в фиде → без
  цены — это покрытие фида, не баг).
- **Уже созданные плохие draft-объявления не лечатся сами.** Новая логика гарантирует корректную
  сборку/repair только для новых созданий; старые черновики с недобором заголовков/картинок нужно
  либо repair-ить отдельно по `ad_id`, либо пересоздавать.

### Имитация-прогон по слепку Павлова (porg-ozge4ntu, 2026-06-24) — 3 фикса
Полная имитация обеих кнопок на слепке Павлова (61 РК: tp1×6, tp2×6, tp5×1, tp6×38, tp7×10),
аккаунт на исчерпанном агентстве (0 баллов) → весь набор шёл по куке. Найдено и исправлено:

- **#1 tp6/tp7 `TEXT_LENGTH_WITHOUT_TEMPLATE_MARKER` (заголовок >56).** В блоке UAC (Мастер/Товарка)
  кап длины `[:56]` стоял ДО `_coherent_discounts`, а когерентность УДЛИНЯЕТ строку (разделители
  тысяч `890000`→`890 000`, замена суммы на эталонную) → финальный заголовок >56 → 400 от UAC.
  Фикс: финальный кап длины ПОСЛЕ `_coherent_discounts` (как в `_responsive_ad`: cap идёт после
  coherent). `blueprint.py` ~6752. Порог проверен live: 56 проходит, 58 — нет.
- **#2 tp6/tp7 `SitelinkDefectIds...SITELINK_TITLE_TOO_LONG`.** `campaign._norm_sitelinks` (воронка
  быстрых ссылок UAC) НЕ резал длину — M3-сгенерированный заголовок ссылки >30 → 400. Фикс: кап
  `title[:30]`/`description[:60]` (как в `_norm_sitelinks_for_v501`). `campaign.py` `_norm_sitelinks`.
- **#3 РСЯ по куке без картинок.** `_tp1_pack_groups` картинки не грузил («текстовое РСЯ — фолбэк»).
  При 0 баллов залить новую картинку нельзя (`adimages.add`→152), но ПЕРЕИСПОЛЬЗОВАТЬ уже залитые
  в аккаунт — можно. Новый `_grid_account_image_hashes(login)` читает `{basename→imageHash}` по куке
  (Grid, без баллов); `_tp1_pack_groups(image_map=…)` матчит картинки группы (как в v5:
  `read_slepok_images ∥ read_images`) по basename → `image_hashes`. Live: Марки 34/34 объявления
  с картинками (было 0). Покрытие растёт по мере «созревания» аккаунта.

**Проверено live (porg-ozge4ntu):** tp1 РСЯ — группы 34–150, заголовки/тексты/быстрые ссылки
(`inheritableSitelinkSet`)/уточнения (`inheritableCallouts`)/картинки; tp2 Поиск — 150 групп;
tp6/tp7 (Мастер/Товарка) — создаются ЧЕРНОВИКАМИ (`launch=False`, контент M3 поитемно) с 5 картинками
+ 8 ссылками. ⚠️ Авто-публикации НЕТ ни у одного типа — см. правило ниже.

### ⛔ ПРАВИЛО: ВСЕ кампании создаются ТОЛЬКО ЧЕРНОВИКАМИ
Сервис **никогда не публикует автоматически** (публикация = ручной шаг в Директе после проверки).
`launch` принудительно `False` в `api_create_set` и `api_create` для ВСЕХ типов, включая UAC
tp6/tp7 (раньше они уходили на показы при «Создать и опубликовать» — исправлено). ЕПК tp1–tp5 и так
всегда DRAFT (`_create_tp1_campaign`/tp3/tp5 → `launch=False`). Кнопка «Создать и опубликовать»
отличается от «Быстрых черновиков» лишь источником контента (M3/ИИ поитемно, `stream_content`), но
РК всё равно DRAFT. Проверено: `launch=true` в payload → `launched=False`, статус в Директе DRAFT.
